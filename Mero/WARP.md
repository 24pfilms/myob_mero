## Project Overview

**Mero** is an AI-powered infinite canvas application built with React 19 and TypeScript. It combines traditional whiteboard functionality with cutting-edge AI capabilities including image editing (Nano Banana), video generation (Veo 2), and conversational AI (Google Gemini).

## Architecture Overview

### Core Technology Stack
- **Frontend**: React 19.1.1 with TypeScript 5.8.2
- **Build Tool**: Vite 6.2.0 (dev server runs on port 3001)
- **Canvas Engine**: Custom implementation using D3.js for pan/zoom
- **Styling**: Tailwind CSS (via CDN)
- **AI Services**: Google Gemini, Fal.ai (Nano Banana, Veo 2)
- **Database**: Dexie.js (IndexedDB) with localStorage migration

### Key Application Structure

```
App.tsx                    # Main app component, tool selection logic
├── components/
│   ├── Board.tsx         # Infinite canvas container & coordinate system
│   ├── BoardItemComponent.tsx    # Individual canvas items
│   ├── Toolbar.tsx       # Main toolbar with positioning
│   ├── AiAssistantModal.tsx     # Gemini AI chat with speech recognition

│   ├── useBoard.ts       # Core canvas state & coordinate transformations
```

### Canvas Coordinate System
The app uses a **DOM-based coordinate transformation** system:
- Screen coordinates → Canvas world coordinates: `(screenPos - translation) / scale`
- World coordinates stored in `BoardItem` objects
- Pan/zoom state managed in `PanZoom` interface: `{x, y, k}`
- Visual placement uses temporary DOM elements for pixel-perfect accuracy

### Zoom & Pan Controls (Oct 13, 2025 - FIXED)

- **Browser Zoom Prevention**: Ctrl+Wheel blocked in index.html

### State Management Pattern

### Coordinate & Transform System
- All items have `{x, y, width, height, zIndex, rotation?}`
- Canvas uses CSS transforms: `translate(panZoom.x, panZoom.y) scale(panZoom.k)`
- Resize handles positioned via calculated percentages
- DOM-based placement eliminates coordinate drift issues

### Zoom/Pan Troubleshooting
If zoom stops working:
1. Check browser console for "Board wheel event" logs
2. Verify `onWheel` prop is passed from App.tsx to Board.tsx
3. Check that browser zoom (Ctrl+Wheel) is blocked in index.html
4. Ensure toolbar is rendered via Portal in Toolbar.tsx (line ~390)
5. Hard refresh browser (Ctrl+Shift+R) to clear cache

### Tool Selection Debugging
If shapes/items don't instantiate on canvas:
1. Open browser console and click a tool button
2. Look for these logs in sequence:
   - "🔘 ToolButton clicked!" (button received click)
   - "🔘 Calling onClick handler" (handler executing)
   - "🔧 Toolbar: [Tool] button clicked" (tool-specific handler)
   - "🎯 Tool selected:" (App.tsx handleToolSelect)
   - "📌 pendingTool state changed" (React state updated)
3. For shapes menu specifically:
   - "🟢 SHAPE MENU IS RENDERING NOW!" (menu visible)
   - "🔶 ShapeMenuItem clicked!" (shape selected)
   - "🔧 Toolbar: Shape button clicked: [ShapeType]" (shape handler)
4. When clicking canvas:
   - "🚨 BOARD DIV CLICKED - RAW EVENT" (canvas received click)
   - "🖄️ Canvas clicked! Pending tool: [object]" (should NOT be null)
   - Item should appear on canvas

## Database Architecture

### Database Initialization
- **Critical**: Database must be initialized using `useDatabase` hook in `App.tsx`
- **Loading States**: App shows loading screen while database initializes
- **Error Handling**: Displays user-friendly error with retry and reset options
- **Migration**: Automatically migrates localStorage data on first launch

### Migration System
- **Automatic Migration**: From localStorage to IndexedDB on first load
- **Image Handling**: Data URLs converted to binary Blobs for efficiency
- **Schema**: Multi-board support with folders, items, and image data tables
- **Migration Flag**: Set in localStorage to prevent duplicate migrations

### Development Database Commands
```javascript
// In browser console:
import { db } from './src/db/Database.js';

// Check database status
await db.getDatabaseInfo();

// Clear all data (for testing)
await db.clearAllData();

// Reset database completely
localStorage.clear();
indexedDB.deleteDatabase('MeroCanvasDB');
window.location.reload();
```

### Board Manager Integration
- **Requires Database**: BoardManager uses `useBoardManager` hook which depends on database
- **Services Used**: BoardService, FolderService, ItemService
- **State Management**: Separate from main canvas state in `useBoard`

## Performance Considerations

### Canvas Optimization
- **Item Rendering**: React components with optimized transforms
- **Large Canvas**: Items outside viewport still render (future optimization needed)
- **Image Storage**: Blobs in IndexedDB prevent localStorage quota issues
- **Smooth Animations**: 60fps with CSS transforms and D3.js

### Memory Management
- Large images stored as IndexedDB blobs, not data URLs
- Generated content (AI images/videos) cached but not persisted
- Undo/redo system limits history size to prevent memory leaks
